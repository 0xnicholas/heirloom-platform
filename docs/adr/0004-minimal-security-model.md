# ADR-0004：最小安全模型（v1）

- **状态**：已接受（2026-08-16）
- **来源**：wayfinder 票 [#9 安全模型最小版](https://github.com/0xnicholas/heirloom-pro/issues/9)，父图 [#1](https://github.com/0xnicholas/heirloom-pro/issues/1)
- **输入**：[research/ts-postgres-stack](https://github.com/0xnicholas/heirloom-pro/tree/research/ts-postgres-stack)（#4：行级权限应用层注入、RLS 仅纵深防御）、[research/oss-landscape](https://github.com/0xnicholas/heirloom-pro/tree/research/oss-landscape)（#3：「DSL 声明→编译进 SQL」路线）、[ADR-0001](0001-ontology-language-core-semantics.md)（#5）、[ADR-0002](0002-storage-engine-mapping.md)（#7 查询包）、[ADR-0003](0003-action-semantics.md)（#8 移交：动作权限边界、审计主体、拒绝记录、入参不脱敏评估）
- **关系**：#8 的「user 类条件归 #9」在此兑现；读过滤编译进 #7 的查询包；#6/#10 拿到边界输入

## 背景

根决策锁定安全范围 = 实体级 RBAC，v1 无 UI、单租户自部署、SDK+API 是第一界面。Palantir 的安全面是标记格 + 细粒度 ACL + 组织边界，为大型多租户治理而生；Heirloom 要的是自部署小团队能用、规格面最小的模型。#3 调研确认「类型化模型+动作+实体级安全」是开源空档，且同类系统共识是「DSL 声明→编译进 SQL」；#4 确认 Kysely 应用层注入、RLS 仅作纵深防御。

## 决策

1. **平台内置主体**：User / Group / ServiceAccount 是引擎内置系统表，不在本体中；认证身份先于任何本体存在（引导需要）。组**扁平不嵌套**（无传递闭包解析）；服务账号与用户**同构**——有 id、可入组，`ctx` 语义一致。**理由**：认证必须能引导（首个管理员在本体存在前就要能登录）；主体不随用户本体演化。**被否**：本体内主体（引导循环依赖、权限 DSL 无法预知用户属性形状）；混合（内置身份+本体内用户对象，v1 规格面翻倍）。

2. **真超管旗**：用户表内置 `isAdmin`，绕过**一切**权限检查（含行级过滤），可管理本体、主体与授权。部署时经 CLI/环境变量引导首个超管，后续由超管授予。**理由**：自部署需要救援通道；绕过逻辑一处实现处处生效。**被否**：全授近似超管（新权限部类要记得补授，漏授即锁死，行级过滤对超管仍生效）；超管仅治平台（「能改权限」事实上已能间接获得任何访问，却少了数据救援通道）。

3. **读授权 = 类型级 + 谓词式行级**：授权 = 主体（用户/组/服务账号）× 对象类型 ×（可选）行级谓词。谓词用**查询包同款过滤算子**（`eq`/`in`/`contains-any`…，ADR-0002）+ `ctx` 常量（`ctx.userId`、`ctx.groups`）写成布尔表达式，编译成 SQL WHERE 片段；多授权 **OR 并集**；无谓词授权 = 全类型可见；无任何授权 = **fails-closed 零行**（不是报错）。所有权、密级标记都不是机制，是建模模式（owner 属性 + 谓词；classification 枚举 + 谓词）。**理由**：一套算子两处复用（查询+权限），表达力同时覆盖所有权与标记两种风格。**被否**：所有权式（表达不了按部门/密级切分）；标记 lattice（标记本体+格关系+传播规则，规格面最重）；逐对象 ACL（管理成本爆炸，导入即噩梦）。

4. **谓词仅限本类型属性**：授权谓词只能引用被授权类型自身标量属性 + `ctx` 常量，无链接游走；跨类型切分（「按项目所在部门看任务」）用反规范化建模纪律解决（Task 上放 orgId）。**理由**：谓词编译成纯 WHERE 片段无 join，与 RLS 纵深防御生成对齐。**被否**：本类型+一跳链接（每次读取强制 join、缓存与 RLS 复杂度上升、「链接对象不可见时谓词怎么算」要定义）。

5. **查询传播 = 静默收窄**：行级谓词编译进**每个**对象读取 SELECT——主查询、`include`（≤2 跳按各自行级谓词过滤，不可见者剔除：多值链接变短、单值变 null）、`count`、游标分页全部一致。过滤跟一跳链接属性**不要求**对被跟类型有读授权，但**永不返回**被跟对象本身——泄漏面限于「能从过滤结果推断被跟对象属性」（如二分探测项目名），写入规格已知限制。**理由**：与过滤器语义同构；报错会让带链接的查询随授权漂移随机失败。**被否**：不可见即报错（可发现性好但客户端体验不可稳定预测）。

6. **动作权限 = 白名单 + 代码内判**：写路径唯一授权是主体→动作白名单（无参数谓词）。「谁能对哪行做」的行级条件在 `execute` 内用 `ctx.userId`/`ctx.groups` 自行判断，不满足抛结构化 **`PermissionDenied`**（与 `ValidationFailed` 同形的结构化异常）。`execute` **全量可见数据**——行级谓词只管读面，动作本身就是被治理的写路径。**理由**：代码即配置与 ADR-0003 同构；授权面可静态审计；服务账号批量导入（#11）天然要写全量，不卡。**被否**：带参数谓词的授权（要对参数类型再定义一套谓词词汇表）；编辑集可见性联动（导入/管理动作被卡死，要开例外，事务内检查语义微妙）。

7. **认证 = 仅静态 PAT**：服务端生成的不透明随机 token（服务端存储、可吊销），`Authorization: Bearer` 传递；无密码、无登录流——人用户的 token 也由超管签发（CLI/管理 API）。**理由**：v1 无 UI，登录流无处安放；自部署小团队可能没有 IdP；签发/吊销/校验三个动作规格面最小。**被否**：PAT + OIDC 委托（多一套部署依赖与配置面）；自管密码（存储/重置/防暴破全套进规格，无 UI 时价值有限）。OIDC → v2。

8. **授权是运行时数据**：主体、组、读授权（含谓词表达式）、动作白名单全部经超管的管理 API/CLI 增删查；本体 DSL 只声明结构，不含授权。**理由**：授权随人员进出高频变更，不应触发代码部署。**代价**：授权无代码审查/版本化（导出备份用管理 API 解决）；谓词引用属性 apiName，本体演化时的校验联动归 #6。

9. **拒绝记录 = 独立安全日志**：引擎内置只追加安全日志，认证失败（无效 token）与授权拒绝（白名单拒绝、`PermissionDenied`）各一行：主体（可知时）、动作 apiName、原因、时间戳。查询不落（fails-closed 零行无法区分拒绝与空集——这是特性）。审计日志保持 ADR-0003「已提交动作才落」的纯度；审计行记主体 id + 主体类型（用户/服务账号）+ 所用 token id。#8 移交的入参不脱敏评估：**维持不脱敏**（token 永不出现在入参），作为已知限制写入规格。**被否**：并入审计表（破坏「回滚=无事发生」语义，认证失败无动作可挂）；不记录（越权尝试无据可查）。

## 与 Palantir 的对齐 / 偏离

| Palantir 机制 | Heirloom v1 | 对齐/偏离 | 理由 |
|---|---|---|---|
| 权限编译进查询（安全过滤随读强制） | ✓ 谓词编译进每个 SELECT | ✓ 对齐 | 同为「声明→编译进 SQL」路线 |
| 标记格 + 传播规则 | ✗ 谓词式建模模式 | ✗ 偏离 | 格代数规格面重；谓词同时覆盖所有权与标记风格 |
| 细粒度 ACL / 组织边界 | ✗ 主体→类型/动作 + 行级谓词 | ✗ 偏离 | 自部署单租户；ACL 管理成本不成比例 |
| 动作权限含对象级检查 | ✗ 白名单 + 代码内判 | ✗ 偏离 | 代码即配置；导入/管理类动作需要全量写 |
| 多种认证（OIDC 等） | ✗ 仅静态 PAT | ✗ 偏离 | 无 UI；自部署最小面；OIDC → v2 |

## 后果

- #6（本体定义与演化）拿到输入：演化变更属性 apiName/类型时须校验引用它的行级谓词（破坏即拒绝或要求同步迁移——策略归 #6 定）。
- #10（API 形态）拿到输入：`PermissionDenied` 的线上编码与状态码（403 类）；白名单拒绝 vs 参数不存在（404 类）的区分；管理 API 端点形状（主体/组/授权/token 签发吊销）；安全日志查询端点；无授权类型的 404-vs-空集语义（零行响应）。
- #11（数据接入与部署）：导入用服务账号 + 超管签发 token；导入不经动作（ADR-0003 已定），行级谓词不影响写路径。
- 超管绕过 = `isAdmin` 旗在认证层短路全部检查，实现上是最外层单点 if，不是「把所有权限授予一遍」。
- 已知限制（写入规格）：过滤跟一跳链接的推断泄漏面；入参不脱敏；授权无版本化。
- OIDC/外部 IdP 集成、授权的声明式导入（DSL sync）→ v2。
