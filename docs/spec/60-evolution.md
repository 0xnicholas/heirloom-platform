# 本体定义与演化

> **范围**：DSL 工程形态与注册表物化、push 权威模型与收敛执行、变更三档矩阵、v1 迁移口径、status 生命周期、push 联动校验、对外兼容口径。
> **不含**：push/接入端点线上编码（[30](30-api.md)）；部署与引擎 schema 迁移（[70](70-operations.md)）；物理映射基线（[40](40-engine.md)）。
> **素材**：[ADR-0007](../adr/0007-ontology-evolution.md)（#6 决议全文）；CLI push 传输机制 ADR-0005 决议 7。
> **待落位**：无。
> **验收线**：深规格（[#13](https://github.com/0xnicholas/heirloom-pro/issues/13) 决议：逐条规范性陈述、示例内嵌、总表归附录）

## 1. 定位：本体是运行时定义

本体进入引擎的唯一方式 = **本体推送（push）**：CLI 在本地求值本体 TS 模块，把注册表物化为定义 JSON，推管理端点。本体是**运行时定义而非部署物**——演化不需要重启，与「授权是运行时数据」（[50](50-security.md) §9）同构。

两条迁移平面**必须**分清：

| 平面 | 触发时点 | 迁移对象 | 归章 |
|---|---|---|---|
| 本体 DDL | push 收敛时 | 本体对象表/链接表/约束 | 本章 |
| 引擎 schema 迁移 | app 启动时 | 引擎自身系统表（主体/授权/审计/安全日志等） | [70](70-operations.md) |

## 2. 权威模型：全量期望态 + 服务端权威

### 2.1 客户端（CLI 物化）

- CLI **必须**在本地 Node 进程求值本体 TS 模块——类型/属性/链接/动作/queryFn 注册进**同一 registry**——提取物化为**定义 JSON**，以**全量期望态**整体 PUT 管理端点。
- 定义 JSON **必须**语言中性：结构以 JSON 原生表达；动作/queryFn 的 `execute` 函数体以源文本随定义传输（服务端进程内执行，[20](20-actions.md) §1）。线上编码归 [30](30-api.md)。
- 服务端**不得**提供第二定义入口（增量 patch、Git 权威服务端镜像均被否——diff 归客户端则并发/幂等语义复杂；镜像 = ADR-0005 已否的挂载变体）。

```bash
heirloom ontology apply ./ontology
# Node 求值模块 → registry 提取 → 定义 JSON → PUT 管理端点（端点形状见 30）
```

```jsonc
// 定义 JSON（摘录示意，字段形状归 30）：期望态 = 类型/链接/动作/函数全体
{
  "objectTypes": [{ "apiName": "employee", "status": "active", "properties": [/* … */], "links": [/* … */] }],
  "structs":     [/* … */],
  "actions":     [{ "apiName": "hire-employee", "params": { /* … */ }, "execute": "/* 函数体源文本 */" }],
  "functions":   [/* … */]
}
```

### 2.2 服务端权威态

服务端**必须**持久保存三件：**当前生效定义** + 单调递增 **revision（本体修订号）** + push 审计行。客户端 Git 仓库只是期望态的出处，**不是**运行时权威。

## 3. 收敛执行：diff → 分类 → 单事务

push 到达后，服务端按固定管线执行：

1. diff(当前生效定义, 期望态) → 变更集；
2. 变更分类（§4 三档）；
3. 生成 DDL + 元数据更新 + 引用校验（§7）；
4. **Postgres 事务性 DDL，单事务全成全败**。

规范性陈述：

- **必须**幂等：重复推同一期望态结果一致；期望态 == 当前生效定义 → **no-op**：不涨 revision、不落 push 审计行。
- 成功收敛 → revision +1，落一条 push 审计行：

| 字段 | 内容 |
|---|---|
| 主体 | 发起主体（用户/服务账号）+ token id |
| 时间 | 时间戳 |
| revision 区间 | from → to |
| 变更计数 | 按矩阵逐条目计数（自动/数据校验各类） |

- DDL 生成**必须**按三档分别产出：自动 = `ADD COLUMN`/建表；数据校验 = `UNIQUE INDEX`/替换 `CHECK`/元数据回填；并支持**事务内探测**（行数、引用计数）。物理基线（列型/约束承载）见 [40](40-engine.md)。
- 并发 push **应当**被串行处理（后到者基于最新生效定义 diff；实现用事务锁或队列，不进规格）。

## 4. 变更三档矩阵（normative）

每条 diff 变更**必须**恰归一档，三档封闭。任一变更落入拒绝档、或任一数据校验档探测不过 → **整个 push 拒绝**（单事务语义，无部分收敛）。

### 4.1 自动档（DDL 即时，无存量数据依赖）

| 变更 | 处置 |
|---|---|
| 加对象类型 | 建表（系统列起底，[40](40-engine.md) §2） |
| 加可选属性 | `ADD COLUMN`（可空；存量行为 NULL） |
| 加可选链接 | `1:1`/`1:N` 加可空外键列；`M:N` 建链接表 |
| 加 struct 定义 | 纯注册（无物理效应，直至被属性引用） |
| 放宽：required → 可选 | `DROP NOT NULL` |
| 放宽：扩 `length` | 替换 `CHECK`（放宽不破存量） |
| 放宽：enum 加值 | 替换 `CHECK`（值集超集） |

### 4.2 数据校验档（尝试执行；存量不过 → 整事务拒绝）

| 变更 | 校验/处置 |
|---|---|
| 删**空**类型/属性/链接 | 事务内探测行数/引用计数 = 0 → 过；否则拒 |
| 加 `unique` | 建 `UNIQUE` 索引扫存量；存量冲突 → 拒 |
| 收紧 `range` / `length` | 新 `CHECK` 全表校验存量；违例 → 拒 |
| 加 `required` **带静态 default** | PG 11+ 元数据-only（无表重写）；default 照常作用于存量 |
| enum 删值且**无**存量引用 | 事务内探测引用计数 = 0 → 替换 `CHECK` 过 |

### 4.3 拒绝档（不得自动安全化）

| 变更 | 理由 |
|---|---|
| 改标量类型（如 string → integer） | 存量值域不可判读 |
| 重命名 `apiName` | = 删 + 加，数据不迁 |
| 可选 → required 无 default | 存量行无值可填 |
| enum 删值且**有**存量引用 | 存量引用该值的行必违新 `CHECK` |

- 拒绝响应**必须**携带出路建议（§5 三通道之一，按变更类型指路）；错误码与响应编码归 [30](30-api.md)。
- 自动档对既有读者向后兼容（新列可空、只增不减），见 §8。

## 5. v1 无迁移语言

拒绝档的官方出路 = **既有通道**，不存在迁移脚本语言：

| 通道 | 适用 |
|---|---|
| 一次性动作 | 事务内改写存量（如重命名：加新属性[自动] → 动作搬值 → 删旧属性，分多次 push） |
| 接入端点重灌 | 全量数据形态变更（删类型 → 重灌，[70](70-operations.md) §2） |
| 外部同步器 | 数据在外部系统有权威副本（[70](70-operations.md) §5） |

- **被否**：Prisma 式 migration 脚本文件（迁移语言整包进规格，与最小可用相悖）；`--allow-data-loss` 强制通道（一次性误操作即永久丢数据，与平台谨慎口径相悖）。

## 6. status 生命周期 = 纯元数据

- 三值封闭：`experimental` / `active`（默认）/ `deprecated`；携带于每个类型/属性/链接（[10](10-language.md) §1）。
- introspection 与管理 API **必须**可见可改（[30](30-api.md)）。
- 运行时**零强制**：`deprecated` 类型/属性/链接**必须**仍可正常读写（查询、动作、链接语义不变）。
- 删除 `deprecated` 类型仍走三档矩阵——与删 `active` 同规则，**「deprecated ≠ 可直接删」**。
- 无 deprecation window、无自动弃用广播机器。

## 7. push 联动校验（fail-closed）

本体、动作、queryFn 是**同一 registry、同一次 push、同一事务**收敛的整体。push 事务内**必须**校验以下引用（封闭清单）：

| 引用方向 | 悬空后果 |
|---|---|
| 行级谓词 → 被删属性（[50](50-security.md) §9） | 谓词编译进 SQL，悬空即破 → 拒 |
| 动作/queryFn 函数体 → 类型/链接（编辑操作、遍历） | 运行时必炸 → 拒 |

- 动作/queryFn 自身的增、删、改为**纯注册面变更**（自动档语义，无存量数据依赖）。
- 运行时授权对被删动作的悬空白名单条目**不在**校验范围（normative 注记：不对称是原理性的——谓词要编译进 SQL 必须可解析；惰性授权条目无害，调用即 404，超管经管理面清理）。
- 定义结构校验（`apiName` 命名规则、同型双链接反向名派生冲突等）在变更分类**之前**先行拒绝（[10](10-language.md) §4）。

## 8. 对外兼容口径 = 无兼容机器

- SDK 的 TS 类型从本体源码仓库**同源编译**；服务端**不得**签发 SDK。
- REST 消费者面向 `apiName` 契约（[30](30-api.md)）。
- **「breaking change」的公开定义 = §4.3 拒绝档清单**（写入 API 文档）；自动档对既有读者向后兼容（新列可空、只增不减）。
- **被否**：API 版本协商（/v2/ 并行本体、多版本本体/谓词并行语义整包进规格）；弃用自动广播（与 status 纯元数据一致）。

## 9. 已知限制与 v2（详见 [90](90-appendix.md)）

重命名不迁数据；可选 → required 无 default 不可自动化；无迁移语言（三通道为官方出路）；无降级（承 [70](70-operations.md)）。
