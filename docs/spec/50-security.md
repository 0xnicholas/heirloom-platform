# 安全

> **范围**：主体模型、超管、认证（PAT）、读授权（类型级 + 谓词式行级）、查询传播语义、动作授权两层、运行时授权数据、安全日志。
> **不含**：动作执行语义（[20](20-actions.md)）；管理端点形状（[30](30-api.md)）；存储注入点（[40](40-engine.md)）。
> **素材**：ADR-0004（安全模型九决策）、ADR-0002（谓词算子同源）、ADR-0003（PermissionDenied）、ADR-0008（403 双 code）。
> **待落位**：无。
> **验收线**：深规格（[#13](https://github.com/0xnicholas/heirloom-pro/issues/13)：逐条规范性陈述、总表归 [90](90-appendix.md)）

## 1. 信任模型

- 单租户自部署；认证身份**先于**任何本体存在（引导需要）；主体是引擎**内置系统表**，不在本体中。
- 最小面：无密码、无登录流、无外部 IdP（OIDC → v2）；授权是**运行时数据**（非代码部署物）。

## 2. 主体模型

| 主体 | 说明 |
|---|---|
| User（用户） | 人；token 由超管签发 |
| Group（组） | **扁平不嵌套**（无传递闭包解析）；主体可入多组 |
| ServiceAccount（服务账号） | 与用户**同构**：有 id、可入组、`ctx` 语义一致；用于接入/同步器 |

- 本体内不得定义主体类型（引导循环依赖；权限 DSL 无法预知用户属性形状）。
- `ctx.groups` = 用户所属组的**直接成员集合**（扁平展开，无嵌套解析）。

## 3. 超管（isAdmin）

- 携带 `isAdmin` 旗的用户**绕过一切权限检查**（含行级过滤）——认证层最外层单点短路，非「授予所有权限」。
- 部署时经 CLI/环境变量引导**首个**超管；后续超管由超管授予。
- 救援通道语义：权限配置失误时不至锁死。

## 4. 认证 = 仅静态 PAT

- 服务端生成的不透明随机 token（服务端存储、可吊销），`Authorization: Bearer` 传递。
- 人用户与服务账号的 token 同构；签发/吊销/列表走管理面（[30](30-api.md)；明文仅签发时返回一次）。
- 无密码/登录流/OIDC（→ v2，[90](90-appendix.md)）。

## 5. 读授权 = 类型级 + 谓词式行级

授权 = 主体（用户/组/服务账号）× 对象类型 ×（可选）**行级谓词**。

- 谓词词汇 = 查询包同款算子（[40](40-engine.md) §6）+ `ctx` 常量（`ctx.userId`、`ctx.groups`），写成布尔表达式，**编译进 SQL WHERE 片段**。
- 组合语义：多授权 **OR 并集**；无谓词 = 全类型可见；**无任何授权 = 零行**。
- **fails-closed 而非报错**：零授权、谓词全不匹配 → 200 空集（静默收窄，见 §7）。
- 所有权（owner 属性 + 谓词）、密级标记（classification 枚举 + 谓词）都是**建模模式**，非机制。

## 6. 谓词仅限本类型属性

- 谓词**只能**引用被授权类型自身标量属性 + `ctx` 常量，**无链接游走**（纯 WHERE 片段、无 join）。
- 跨类型切分（「按项目所在部门看任务」）用**反规范化建模纪律**解决：Task 上放 `orgId` 冗余属性。
- 理由（normative 注记）：无强制 join、与 RLS 纵深防御生成对齐、免定义「链接对象不可见时谓词怎么算」。

## 7. 查询传播 = 静默收窄

行级谓词编译进**每个**对象读取，全查询面一致：

| 查询面 | 行为 |
|---|---|
| 主查询 | 谓词过滤后返回 |
| `include`（≤2 跳） | 各跳按**各自**行级谓词过滤；不可见者剔除——多值链接变短、单值变 null |
| `count` | 同过滤器、同谓词 |
| 游标分页 | 与主查询一致 |

- 一跳链接属性**过滤**不要求对被跟类型有读授权，但**永不返回**被跟对象本身；泄漏面限于「能从过滤结果推断被跟对象属性」（如二分探测）——已知限制（[90](90-appendix.md)）。
- 不可见**不报错**（报错会让带链接的查询随授权漂移随机失败；零行与拒绝不可区分——这是特性）。

## 8. 动作授权 = 两层（与 [20](20-actions.md) §7 联动）

| 层 | 机制 | 拒绝 | 日志 |
|---|---|---|---|
| 引擎层 | 主体（或组）→ 动作**白名单**；无参数谓词 | 403 `WHITELIST_DENIED` | 安全日志 |
| 代码层 | `execute` 内 `ctx.userId` / `ctx.groups` 自判；不满足抛 `PermissionDenied` | 403 `PERMISSION_DENIED` | 安全日志 |

- `execute` 内代码**全量可见数据**（行级谓词只管读面）；行级写条件就是代码层判定。
- 白名单授权主体为用户或组；导入/管理类动作的全量可见是设计结果，非漏洞。

## 9. 授权 = 运行时数据

主体、组、读授权（含谓词表达式）、动作白名单全部经**超管的管理 API/CLI** 增删查（端点形状见 [30](30-api.md)：subjects / groups / read-grants / action-grants / tokens）。

- 本体 DSL 只声明结构，**不含**授权——授权随人员进出高频变更，不应触发代码部署。
- 代价（normative 注记）：授权无代码审查/版本化；导出备份用管理 API 解决。
- 谓词引用属性 `apiName`：本体演化的联动校验（fail-closed）归 [60](60-evolution.md) §push 校验。

## 10. 安全日志（独立于审计）

引擎内置**只追加**安全日志，与审计日志（[20](20-actions.md) §10，只记已提交动作）分立：

| 条目 | 记录 |
|---|---|
| 认证失败（无效 token） | 主体（可知时）、原因、时间戳 |
| 白名单拒绝 | 主体、动作 apiName、原因、时间戳 |
| `PermissionDenied` | 主体、动作 apiName、原因、时间戳 |

- **查询不落日志**：fails-closed 零行无法区分拒绝与空集——这是特性（防以日志探测授权面）。
- 回滚动作不落审计，但授权拒绝已落安全日志（拒绝发生在事务前/中，与提交无关）。

## 11. 已知限制与 v2（详见 [90](90-appendix.md)）

仅静态 PAT（OIDC/密码 → v2）；授权无版本化；一跳过滤的推断泄漏面；审计入参不脱敏；授权声明式导入（DSL sync）推迟。
