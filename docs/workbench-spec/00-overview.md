# 概述

> **范围**：工具定位（顾问伴侣工具，非平台 UI）、根决策（权威链不变/读写模型/本地单机）、与平台规格的关系、范围与非目标、完成判据。
> **不含**：平台本体语义（[docs/spec/](../spec/README.md)）。
> **素材**：[图 #16](https://github.com/0xnicholas/heirloom-pro/issues/16) 根决策与 Out of scope。
> **验收线**：深规格工具版（[#22](https://github.com/0xnicholas/heirloom-pro/issues/22)：逐屏布局与交互、逐流程状态机、错误/边界清单）

## 1. 定位：顾问的本地伴侣工具

建模工作台 = Heirloom 生态的**本地伴侣工具**：陪顾问跑一场**术语工作坊**（倒词 → 判定向导 → DSL 草稿 → 贴回仓库 → 术语表交付），面向**非技术领域专家**与投影场景。它**不是**平台 UI——Heirloom v1 无 UI 是平台根决策（[spec/00](../spec/00-overview.md) §2），本工具不改变它。

一句话分工：**平台管运行时，工作台管谈话**——图谱与向导服务工作坊对话，Git 仓库才是权威。

## 2. 根决策（建图锁定，normative）

| 决策 | 值 | 含义 |
|---|---|---|
| 权威链不变 | Git → CLI → push | 工作台**不得**直连引擎、**不得**绕过 `heirloom ontology apply`；唯一产出 = 贴回仓库的 DSL 草稿文件 |
| 读侧 = 求值注册表 | 同源 extractor | 现状本体**必须**经与平台 CLI 同一可执行求值提取（[40](40-eval-channel.md)）——**不得**解析源码文本 |
| 写侧 = 只生成新块 | untracked 草稿 | 既有源码**零改写**（构造性保证：只新建文件）；人贴回、人 commit |
| 平台 v1 规格零改动 | 无任何平台需求 | 唯一依赖 = 平台 CLI 的注册表物化出口（ADR-0007 已规划，spec/10、spec/60）——已有决议覆盖，**不新增**平台需求 |
| 运行形态 | 本地单机 | 顾问笔记本 + 投影工作坊；**零部署、零认证、零网络**（localhost 除外）；Git 仓库即全世界 |
| 规则源 = 主图派生 | ADR-0001~0008 + CONTEXT.md | 判定规则全部从平台决议派生（[10](10-workshop.md) §4），本工具**不得**引入与平台语义冲突的判定 |

## 3. 与平台规格的关系

- 本体语义（类型/链接/动作/演化三档）冲突时，**以 [docs/spec/](../spec/README.md) 为准**；工作台规格只描述工具如何**运用**这些语义。
- 术语表沿用主图 [CONTEXT.md](../../CONTEXT.md) 工作法（同构导出见 [10](10-workshop.md) §7）。
- 阅读路径：本概述 → [10 工作流](10-workshop.md)（心脏）→ [20 界面](20-interface.md) → [30 生成与预检](30-drafting.md) / [40 求值通道](40-eval-channel.md) → [50 技术栈](50-stack.md) / [60 数据](60-data.md) → [80 验收](80-acceptance.md)。

## 4. 范围与非目标（吸收图 #16 Out of scope）

| 项 | 处置 |
|---|---|
| Heirloom 平台内建 UI（本体编辑器/对象浏览器/管理台） | 出界——v2 官方努力，届时另图 |
| 可视化编辑直连 push | **永久否决**（破坏 Git 权威链；读写模型锁死） |
| 数据浏览器/管理台复刻 | 出界（平台 REST/CLI 已覆盖） |
| 多人实时协同编辑；托管/多用户部署形态 | 出界（与本地单机形态矛盾） |
| CSV/Excel 文件导入；自动布局；改写既有块 | v2（[90](90-appendix.md)） |
