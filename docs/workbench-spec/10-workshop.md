# 工作坊工作流

> **范围**：单池双道采集语义、分层三幕问句序、判定向导规则树、话术三句与属性口诀、向导三戒、CONTEXT.md 同构术语表导出。
> **不含**：界面呈现（[20](20-interface.md)）；术语条目字段集与工作簿（[60](60-data.md)）。
> **素材**：[#19 决议](https://github.com/0xnicholas/heirloom-pro/issues/19)全文；[#17](https://github.com/0xnicholas/heirloom-pro/issues/17) 字段节奏/向导三戒/不打断原则；规则树派生自 ADR-0001/0003。
> **验收线**：深规格工具版（#22：逐流程状态机、错误/边界清单）

## 1. 总则：一场工作坊的形状

```
倒词采集（单池双道）→ 第一幕 身份 → 第二幕 织网 → 第三幕 动词 → 生成草稿（30）→ 贴回（30）→ 导出术语表（§7）
```

- 第一设计原则（normative，实证结论）：**不打断工作流**——任何阶段加词/加关联**不得**强迫离开当前页。
- 三幕之间**必须**允许往返重访（判定可回退，§5 三戒之一）；幕间有依赖顺序（§3），不可跳幕深问。
- 工作台全程不阻塞：生成与预检（[30](30-drafting.md)）可多轮迭代，贴回与否由顾问决定。

## 2. 单池双道采集（倒词期）

- **一个输入池**：快速堆词（逐词回车/粘贴多行——行为语义：一行一词入池，去空白、去重提示见 §2.3）。
- **轻标记三值**：每个词可标 名词 / 动词 / **待定**；**待定永远合法**——工具**不得**强判、不得因待定阻塞后续流程。
- **倒词期只要「名字 + 一句话」**（definition 一句话可选）：其余字段**不得**在此阶段出现（字段随判定渐现，防字段轰炸）。
- 名词/动词在判定期分道（[20](20-interface.md) 词汇流按标记着色分组）；采集与判定是**两个节奏**——倒词快、判定慢。
- **被否**：双池双入口（倒词节奏被打断）；完全不标记事后分流（动词浪费判定步数）。

### 2.1 粘贴多行导入

- 客户资产导入 v1 **仅**粘贴多行（CSV/Excel 文件导入 → v2，[90](90-appendix.md)）；粘贴行为 = 按行切分入池，逐行走轻标记。

### 2.2 过滤搜索贯穿

- 词汇池**必须**全程提供过滤搜索——防止重复造词（同义词合并入口挂搜索结果上）。

### 2.3 边界（错误/边界清单）

| 边界 | 行为 |
|---|---|
| 空行/纯空白行 | 静默跳过 |
| 与已有词全同（含同义词表命中） | 高亮提示合并，**不得**自动吞并 |
| 超长词（>80 字符） | 截断警告（与 DSL `length(1,80)` 对齐，标定时收紧） |

## 3. 分层三幕问句序

| 幕 | 对象 | 判定内容 | 幕间依赖 |
|---|---|---|---|
| 第一幕 身份 | 逐名词 | object / struct、业务键、属性选型 | 无 |
| 第二幕 织网 | 全图过关系 | 链接基数、required、载荷→中间对象升级 | **两端类型必已知**（第一幕完成） |
| 第三幕 动词 | 逐动词 | action / queryFn | **作用类型已定**（第二幕完成） |

- **被否**：单术语深走到底（链接对端悬空、动词无的放矢）；三幕 + 自由模式并存（流程定义变松）。
- 幕推进状态**应当**显式可见（进度指示）；重访上幕修改**必须**传播提示（受影响判定重问，不静默改）。

## 4. 判定向导规则树（normative；派生自 ADR-0001/0003，零新语义）

### 4.1 名词道（第一幕起步，第二幕续）

```
名词
├─ 有独立身份？（被单独谈论/引用/计数？——服务端主键的那个"它"）
│  ├─ 否 → struct：无身份嵌入值
│  │        · 嵌入宿主属性位；可复用于多个宿主（v1 唯一形状共享）
│  │        · 不得参与链接、不可独立查询/授权
│  └─ 是 → object 类型
│           · 业务键？（工号/编码类唯一标识 → unique 属性；无则跳过）
│           · 属性选型（§6 口诀 + 九类标量）
│           · 链接判定 → 第二幕
└─ （身份拿不准 → 暂标待定，永远合法）
```

### 4.2 链接判定（第二幕；逐关系全图过）

```
关系（两端类型已定）
├─ 基数三选一：1:1 / 1:N / M:N（从声明方视角）
├─ required？声明后写事务提交时必须已链接
└─ 关系要挂数据（角色/日期/审批状态）？
   ├─ 否 → 直连链接（无载荷——链接永不带数据）
   └─ 是 → 升级：中间对象类型 + 两条 1:N（required）链接
            （Membership 模式；载荷即中间对象的属性）
```

### 4.3 动词道（第三幕）

```
动词
├─ 改变本体状态（要写对象/链接）？ → action（单事务 execute；语义层唯一写路径）
└─ 只读取/投影（纯算不给新事实）？ → queryFn（只读 q 接口位）
（拿不准 → 暂标待定；默认问一句"它办完之后，仓库里多了/变了什么？"——零效应即 queryFn）
```

- 规则树节点即向导步（[20](20-interface.md) 节点详情抽屉承载）；每步选项**封闭**（§5 三戒之二）。
- 规则树与本工具实现**同寿命维护**：平台语义演化（如 v2 链接属性）时，规则树**必须**随 [docs/spec/](../spec/README.md) 同步修订。

## 5. 向导三戒（normative，实证结论）

1. **可回退**：向导任意步**必须**能回到上一步/退出不改状态。
2. **问题克制**：每步一问、选项封闭——**不得**开放追问、不得一次堆多问。
3. **结尾块摘要**：每条判定完成时**必须**给出将生成的 DSL 块摘要预览（承接 [30](30-drafting.md) 生成）。

## 6. 话术与口诀（进向导文案，原文照录）

**客户话术三句**（进向导时的领域翻译，顾问照读）：

1. 「对象引用永远走链接不走属性」
2. 「关系带附件 = 升级成中间对象」
3. 「没有父类型，共用形状用 struct」

**属性选型口诀**：钱 = `decimal`、状态 = `enum`、杂项 = `json`（最后手段）。

## 7. 产出物：CONTEXT.md 同构术语表

- 导出格式与顾问工作法的 CONTEXT.md 术语节**同构**：每条 = **术语 / 定义 / 同义词 / 建模落点**（落点 = apiName 与构造判定，如 `employee → object；工号=unique 业务键`）。
- **一份两用**（normative）：同一份导出 = 顾问自用术语表 + 客户交付物——**不得**养双模板、不得要求顾问手工转写。
- 导出时机：随时可导（判定进行中亦可，未定项标「待定」）。

## 8. 已知限制与 v2（详见 [90](90-appendix.md)）

文件导入 → v2；判定传播提示的粒度（受影响项清单）随实现定；术语表导出 v1 仅 Markdown（其他格式 v2）。
