# 生成与预检

> **范围**：草稿落点与文件命名、草稿迭代制（provenance）、def 生成器（模板+Prettier）、两层预检语义（def 层三档着色 + bun 合并求值）、可贴回门、同名≠改名红灯与出路文案、贴回指引（git 三行）、diff 呈现。
> **不含**：extractor 子进程与兜底细节（[40](40-eval-channel.md)）；界面呈现（[20](20-interface.md) §5）；工作簿字段（[60](60-data.md)）。
> **素材**：[#20 决议](https://github.com/0xnicholas/heirloom-pro/issues/20) + [#18 T1/T3](https://github.com/0xnicholas/heirloom-pro/blob/research/dsl-draft-generation/research/dsl-draft-generation.md) + ADR-0007 三档矩阵（平台 [spec/60](../spec/60-evolution.md) §4）。
> **验收线**：深规格工具版（#22：逐流程状态机、错误/边界清单）

## 1. 草稿落点：git 原生 untracked 新文件

- 草稿 = 仓库内 **untracked 新文件**：完整可编译（含 import 头）、默认 `ontology/<域>.ts`（域 = 工作坊判定建议）、顾问可改名。
- 生命周期（normative）：**贴回 = `git add` + `git commit`**（人的动作）；**放弃 = 删文件**；**评审 = `git diff` + 工作台双层预览**。
- 既有文件**零触碰**是构造性保证——生成器只 `create`，无任何写既有文件路径（根决策，[00](00-overview.md) §2）。
- **被否**：独立导出目录（多一道复制手续）；仅剪贴板（多场次不 practical）。

## 2. 草稿迭代制（provenance；决议缝隙的忠实闭合）

#20 锁定「只生成新块」，而 #21 快捷件与示例卡片含「对既有类型加属性」类判定。两者的唯一自洽读法（本节 normative）：

- **现状注册表 = 磁盘上求值到的一切**（untracked 文件同样被 extractor 求值——求值视图与 git 状态无关）。
- **自产草稿可迭代**：对「本会话工作台生成、尚未贴回」的草稿文件（provenance 记录于工作簿，[60](60-data.md)），再生成时**必须**整体重生成该文件（含增量：加属性/加链接入内）——重生成的是工具自己的未交付产物，不触碰任何非自产文件。
- **既有类型（已贴回或非自产）的修改类判定**：工具**不得**生成改写代码（DSL 无 extend 构造——平台 [spec/10](../spec/10-language.md) 事实；同名重定义在预检② = apiName 冲突 = 红灯，见 §7）。此类判定 → **手工变更指引卡**（人类语言建议 + 档位分析，入术语表与变更卡流，不生成代码、不进贴回）。
- 已知限制与重访条件（ts-morph 改写既有块 / DSL extend 构造）→ [90](90-appendix.md)。

## 3. def 生成器：模板字符串封闭词汇 + Prettier 终排版

- 生成器 = **def 同构模板**：从判定结果组装定义（与 extractor 注册表视图同构的内部表示）→ 模板字符串封闭词汇输出 TS（构建器词汇 = `objectType/structType/link/action/queryFn/p.*`，平台 spec/10 §6；**不得**生成词汇表外的构造）。
- **终态只认 Prettier**：`resolveConfig` 贴仓库自身 `.prettierrc`（无配置用默认）；链式断行**不得**进模板。
- **快照测试穷举锁定输出**：封闭词汇 → 生成器输出快照全覆盖（实现质量的验收手段，normative）。
- **被否**（#18 T1）：ts-morph（AST 操纵对只生成无用武之地；7.1 换 API 风险）；裸 TypeScript printer（押注重构接口）。

## 4. 预检①：def 层三档模拟

- 输入：判定提议 def × extractor 注册表现状（[40](40-eval-channel.md) §4）。
- 比对按平台变更三档矩阵（[spec/60](../spec/60-evolution.md) §4，工具**不得**自创档位）逐条着色：

| 灯 | 档位 | 文案要素 |
|---|---|---|
| 🟢 | 自动（新类型/可选属性/可选链接等 additive） | 「自动档——」+ 一句理由 |
| 🟡 | 数据校验（如加 unique） | 「数据校验档——存量可能不过，push 时服务端终审」 |
| 🔴 | 拒绝（同名异形等） | 「拒绝档——」+ **出路文案**（§7） |

- 本层**纯 def 比对**，不跑引擎、不碰数据（黄档真伪只有 push 时服务端能判——文案**必须**明示）。
- 注记：迭代制（§2）下绝大多数草稿条目落绿档；黄档在 v1 生成面出现频率低（主要命中自产草稿上加约束类），矩阵语义仍**必须**完整实现（供诊断与未来 extend 对齐）。

## 5. 预检②：合并求值（bun extractor）

- 行为：草稿文件与现状本体**一起过 bun extractor**（[40](40-eval-channel.md) §3；~60ms 量级）。
- 检出三类硬伤 → **红并定位**（错误定位回传变更卡与代码预览行）：
  1. **apiName 冲突**（草稿与现状同名——含「想给既有类型加属性」误用重定义的场景）；
  2. **reverse 派生冲突**（同型双链接省略 reverse，平台 spec/10 §4 规则）；
  3. **悬空 thunk**（链接目标类型不存在）。
- 失败时草稿仍可编辑重生成——预检是门不是死路。
- **被否**：仅 def 层比对（冲突要等真 push 才爆）；连真引擎演练（破坏本地零依赖）。

## 6. 可贴回门（normative）

- **红灯锁死**：预检① 任一 🔴 或预检② 任一硬伤 → 「可贴回」disabled。
- **无红即亮**：🟢 全绿或 🟢🟡 混合 → 可贴回亮起（黄=警示放行——数据校验档只有 push 时服务端终审，贴回本身零风险）。
- 注记（两票措辞调谐）：#20 字面「全绿才亮」与 #21「红灯锁死」按被否论证预设调谐为**无红即亮、黄警示放行**——「同名只黄灯」被否的理由（可贴回灯权威性下降）仅在黄≠锁时成立；C 原型按钮实现（`hasRed` 才 disabled）同读法。若按字面全绿锁，黄档（服务端才能判真伪）将无本地出路阻塞主流程。

## 7. 同名 ≠ 改名：红灯 + 零重构

- 触发：草稿意图修改既有类型的 `apiName`（或同名异形重定义）→ 🔴。
- v1 **无改名通道**（平台：重命名 = 删 + 加、数据不迁，拒绝档——[spec/60](../spec/60-evolution.md) §4.3）；工具**不得**做自动改名/refactor。
- **出路文案三选**（原文照录进红灯卡）：
  1. 换一个新 apiName；
  2. 显式删 + 加（数据不迁，明白着来）；
  3. 保留原名，只做允许档变更。
- **被否**：改名向导（拒绝档迁移语义越权进工具层）；同名只黄灯（可贴回灯权威性下降）。

## 8. 贴回指引：git 三行

变更卡尾部固定区（文件名为实际落点）：

```bash
git add ontology/<域>.ts
git commit -m "工作坊产出：<域>域草稿"
# 放弃：rm ontology/<域>.ts
```

- 第三行为**放弃通道注释**（顾问自选）；贴回后 **CLI push 交接**（`heirloom ontology apply`）——引擎侧不动（权威链，[00](00-overview.md) §2）。
- 工具**不得**自动执行 git 命令（贴回是人的动作；工具只生成与预检）。

## 9. diff 呈现：jsdiff 双出口

- `structuredPatch` → UI hunk 渲染（喂 [20](20-interface.md) §5 次层）；`createTwoFilesPatch` → unified 文本（顾问复制用）。
- 行级粒度；纯增量天然无删除行/hunk 噪音（unified diff 最难的部分被「只生成新块」架构性移除）。
- **被否**（#18 T3）：diff-match-patch / 外部 git diff / 自研 LCS；块级 diffArrays → v2 视觉分层可选。

## 10. 状态机（生成→预检→贴回）

```
idle ──生成──▶ drafting（def 组装→Prettier）──▶ checking
checking ──预检①+②──▶ all-green / has-yellow（⚠可贴回亮）/ has-red（🔒锁死+出路）
has-red ──编辑重生成──▶ drafting（循环迭代）
可贴回亮 ──顾问 git 贴回──▶ pasted（工作簿记 provenance 清账；图谱节点转实线——重新求值生效）
任意 ──放弃──▶ abandoned（rm 草稿文件；判定保留在工作簿与术语表）
```

## 11. 已知限制与 v2（详见 [90](90-appendix.md)）

既有类型修改不出代码（指引卡）；黄档命中面窄（矩阵语义完整保留）；无自动改名；unified diff 无块级视觉分层。
