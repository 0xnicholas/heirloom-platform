## 故事叙事（W0–W8，资料性）

冲突规则：叙事与正文各章冲突时，**以各章为准**（#22 决议）。示例域沿用 HR/项目（对齐主图冻结本体）；安全面、终端机等环境素材为场景层补充。

### W0 冷启动（50/60）

```bash
bunx heirloom-workbench ~/clients/acme
# → localhost server（仅 127.0.0.1）→ 自动开浏览器 → 空白图谱 + 词汇流就绪
```

1. 仓库无工作簿：首启初始化空簿 + `.gitignore` 追加 `.heirloom-workbench.json`（60 §1/§7）。
2. extractor 同源通道探测：bun 在 PATH → 求值现状本体（本例空注册表）→ 图谱空、首推第一幕（绿地正常态，20 §8）。

### W1 倒词（10/20）

1. 顾问引导客户倒词：输入框逐词回车（默认待定）+ 粘贴客户 Excel 列名多行（一行一词入池，仅粘贴——文件导入 v2）。
2. 逐条 chips 轻标记：员工/部门/技能/项目→名，录用/调薪/花名册→动，成员关系→待定（待定永远合法）。
3. 倒词期字段只有名字+一句话；中途想补词——任何阶段可回侧栏，不离开当前页（不打断，10 §1）。

### W2 第一幕身份（10）

1. 点「员工」→ 详情抽屉问句区：「它会被单独引用、查询、授权吗？」→ 有身份 → object；下一问业务键：「工号」→ unique 属性。
2. 属性选型口诀落场：薪资→decimal（钱）、状态→enum（状态）。
3. 「地址」→ 纯形状 → struct（嵌宿主 Employee、可复用——不上画布，宿主抽屉内呈现，20 §3.1）。
4. 判定完成 → 块摘要预览（三戒之三）确认；「拿不准的中间对象」标待定继续。

### W3 第二幕织网（10）

1. 全图过关系：「员工—部门」→ 1:N + required（话术照读：对象引用永远走链接不走属性）。
2. 「员工—技能」→ M:N 无载荷 → 直连链接。
3. 「员工—项目」要挂角色/日期 → 话术第二句：「关系带附件 = 升级成中间对象」→ Membership 中间对象 + 两条 required 1:N。
4. 图谱实时长边：基数标注 + required 星标（谈话主角地位）。

### W4 第三幕动词（10）

1. 「录用」「调薪」→ 改数据 → action（「办完之后仓库里多了/变了什么？」）。
2. 「花名册」→ 零效应只读 → queryFn。

### W5 生成草稿（30/40）

1. 点「生成草稿」→ def 组装 → Prettier（贴仓库 .prettierrc）→ 落盘 `ontology/hr.ts`（untracked）。
2. 预检①：新类型/属性/链接/动作全 🟢；预检②（bun 合并求值 ~60ms）：无 apiName/reverse/悬空冲突。
3. 反例演示：把「员工」想改成 apiName `worker` → 🔴 同名≠改名 + 出路三选文案（新 apiName/删+加/保留原名）——红灯锁「可贴回」。
4. 换回原名重生成 → 无红即亮「✅ 可贴回」（黄警示放行，30 §6）。

### W6 贴回（30/00）

1. 变更卡尾部 git 三行：`git add ontology/hr.ts` / `git commit` / `# 放弃： rm`——工具不调 git，贴回是人的动作。
2. 顾问 commit 后：下次求值 hr.ts 已入注册表（求值视图与 git 状态无关）→ 图谱节点转实线；provenance 清账为 `pasted`。
3. 后续：`heirloom ontology apply` CLI push——权威链 Git → CLI → push，引擎侧不动（00 §2）。

### W7 导出术语表（10）

1. 工具导出 CONTEXT.md 同构术语表（术语/定义/同义词/建模落点）：「员工 / 组织成员 / 人力资源、同事 / employee → object；工号=unique 业务键」。
2. 一份两用：顾问粘进自己的 CONTEXT.md，同一份即客户交付物（不养双模板）。

### W8 中断恢复（60）

1. 工作坊中途关浏览器（甚至重启）→ `bunx heirloom-workbench` 重开：术语、判定进度、画布坐标、场次历史、草稿 provenance 全量还原（每次变更即原子写——无保存按钮）。
2. 散场：场次记录落一条（日期/到场人/术语快照），下场继续。
